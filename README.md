# 印度占星排盤(Jyotiṣa)

單一自足的 HTML 檔,直接用瀏覽器開 `index.html` 即可使用。
無建置步驟、無外部請求、無 CDN —— 天文計算引擎
([astronomy-engine](https://github.com/cosinekitty/astronomy), MIT) 整包內嵌。

## 功能

- **本命盤**:Lahiri (Chitrapakṣa) ayanāṁśa 恆星黃道、整宮制(Whole Sign)宮位、上升點
- **分盤**:D1 Rāśi 與 D9 Navāṁśa 北印方盤(SVG 自繪)
- **行星位置**:逆行、燃燒、廟旺落陷、二十七宿與 pada
- **Pañcāṅga**:曜日、Tithi、Nakṣatra、Yoga、Karaṇa
- **Vimshottari 五層層疊**:大運 → 流年 → 流月 → 流日 → 流時,可查任意時刻
- **Ṣaḍbala 逐力表**:位置 / 方位 / 時間 / 動勢 / 自然 / 相映六力齊備,給 virūpa 與 rūpa
  總力(BPHS 27 全章;含年月日時四主、星戰修正)
- **इष्टकष्ट 吉凶果**(BPHS 28.6–12):六力折成吉分／不吉分,吉分大於不吉分則其大運為吉。
  這是原典自帶的「力 → 吉凶果」轉換橋,論斷評分即以此為準,**不使用任何無出處的校準權重**
- **中文論斷**:綜合主星廟旺、落宮、宮主職能、五重友誼、相映、燃燒逆行與層間關係自動生成

## 精度驗證

`tools/` 下有一組對照工具,把 `computeChart` 的原始輸出逐項比對 Swiss Ephemeris:

```bash
npm i                                              # playwright(見 package.json)
node tools/extract-chart.mjs                       # → tools/chart-data.json

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt          # pyswisseph
.venv/bin/python tools/crosscheck.py               # 逐項列出誤差(角秒)
```

七組樣本橫跨 1860–2099、五大洲的實測結果:

| 項目 | 最大誤差 |
|---|---|
| Ayanāṁśa | 0.00″ |
| 羅睺 / 計都 | 0.29″ |
| 上升點 | 1.61″ |
| 太陽 | 4.12″ |
| 木星 | 4.32″ |
| 火星 | 4.78″ |
| 土星 | 6.96″ |
| 水星 | 7.57″ |
| 金星 | 8.69″ |
| **月亮** | **63.55″** |

- **Ayanāṁśa 的三次擬合對 `SIDM_LAHIRI` 七組全數 0.00″**,等於零成本複製了
  Swiss Ephemeris 的 Lahiri 曲線。
- 逆行判定七組全對。
- Vimshottari 起運點另以手算對帳(1990 樣本推至羅睺大運起於 2011-08-06),分秒相符。
- **唯一超標項**:月亮 63.55″ 只發生在 2099 那組;1860–2024 全部樣本的月亮誤差
  都在 3.6″ 以內。成因是內嵌 astronomy-engine 的月球模型在擬合區間邊緣精度下降。
  63″ 相對於一個 pada 的 12000″ 約 0.5%,除非月亮正好落在宿界上,否則不改變論斷。

## 論斷規則的原典依據

解析引擎自稱「BPHS 式」。哪些規則真的對得上原典、哪些偏離、哪些找不到出處,
逐條記在 **[`docs/SOURCES.md`](docs/SOURCES.md)** —— 內含梵文原典、英譯與印地文
版本的直接連結。摘要:

- ✅ 廟旺星座、自然友敵表、火木土特殊相映、Vimshottari 年數 —— 與 BPHS 一致
  (自然友敵表另有自動化測試,依 BPHS 3.55 獨立推導 42 組關係守住)
- ✅ 燃燒容許度(順逆分列 + 月亮)、四級分級相映(BPHS 26.3 pādavṛddhi)、
  廟旺度數與根本三角分段(BPHS 3.49–54)、māraka / badhaka、
  五重友誼(pañcadhā maitrī,BPHS 3.55–58)、
  吉果成數(BPHS 3.59:旺滿／三角 ¾／本宮 ½／友宮 ¼／中性 ⅛／陷·燃燒·敵零)—— 已修正
- ⚠️ BPHS 3.60 後半「凶果反之」**不實作** —— 英譯只有一句概括、無註釋,至少兩種讀法
  會做出完全不同的級距,且查到的兩個來源是同一譯本的轉錄,不構成交叉驗證
- ✅ Ṣaḍbala **六力齊備**:位置 Sthāna(27.1–6,含 ch.6 七分盤)、方位 Dig(27.7–8)、
  時間 Kāla(27.8–17,五子項)、動勢 Cheṣṭā(27.18・24–25a)、自然 Naisargika(27.13–14)、
  相映 Dṛk(27.19,含 ch.26.5–12 的精確相映 spaṣṭa dṛṣṭi),加 27.20 的星戰修正
  —— 六力表另附 इष्ट／कष्ट 兩欄。對帳過程查出**八處**英譯與梵文不合(索引表見
  SOURCES.md 章首「對帳發現一覽」):
  ① 七分盤七級 virūpa 是 **45/30/20/15/10/4/2**(27.3 的 bhūtasaṅkhyā,與 Santhanam
  正文一致),不是坊間流通的 22.5/7.5/3.75/1.875;② drekkāṇa bala 性別序梵文作「男/中性/女」,
  與英譯及通行實務相反;③ 26.6 的相減方向英譯譯反且自身前後矛盾;④ 26.12 木星那半句英譯
  漏了「兩倍」;⑤ नत bala 的簡式讓月火土在**正午**得滿分,與英譯自己上一段「夜曜得力於夜」
  相反;⑥「月的 pakṣa 加倍、日的 ayana 加倍」梵文完全沒有;⑦ 27.11 的吉曜是寫死的
  月水金木四名,英譯註卻加了浮動的吉凶條件;⑧ 28.13 用 `भजेत्`(除)、緊接的 28.14 用
  `हन्यात्`(乘),同段兩詞並用即刻意區分,英譯兩處卻都作 multiply,28.13 方向反了。
  八處都依梵文,理由逐條記在 SOURCES.md
- ✅ 正面驗證:27.15 的 khaṇḍa 讀作 45/33/12,三段和 90 ÷ 23°27′ = 3.838,再 ÷3 = **1.2793**
  —— 恰好是 Santhanam p.277 給的 ayana bala 簡式係數,梵文折線法與英譯簡式互為驗算;
  ahargaṇa 的基準常數則由他 p.270–271 的算例反推、再用他引 Burgess 的 1860 年錨點獨立驗過
- ✅ 交叉驗證:26.5–12 的精確相映公式代入各宮起點,恰好等於 26.3 pādavṛddhi 分級 × 60,
  土/火/木的特例式也各自在 3·10 / 4·8 / 5·9 宮給滿分 —— 與 26.4 的特殊相映吻合
- ⚠️ **僅存的校準常數是 `toneTag` 的五級門檻**(`TONE_MID` / `TONE_HIGH`)—— 吉／凶的
  分界(淨吉分 = 0)由 28.12 給定、有出處,但五級標籤的**間距**原典未言。
  (原先掛在這裡的「各項相加的權重無出處」已於 2026-08-18 隨評分改依第 28 章 इष्टकष्ट 移除;
  七分盤 शुभाङ्क 因尺度與 28.9・11 的互補結構不相容退出合成,連帶燃燒不影響分數 ——
  已查明 28.13 的歸一化救不回此事,見 SOURCES.md 對帳發現 ⑧)
- ❓ 「下層主星距上層主星幾宮」一條在 BPHS 原文裡找不到出處,屬後世實務傳承;
  規則保留,但頁尾已改為分開標示,不再冒用原典背書

論斷規則的回歸測試:

```bash
npm test                         # = node tools/test-rules.mjs,29 項,退版即失敗
```

改動任何會動到吉凶分數的規則時,前後各跑一次校準掃描,比對標籤分佈:

```bash
node tools/calibrate.mjs before.json     # 改動前
node tools/calibrate.mjs after.json      # 改動後
node tools/calibrate.mjs --diff before.json after.json
```
